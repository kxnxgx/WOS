## 1. 現状の把握（概要とシステム構成）

### 概要
本ツールは、店舗別の売上履歴と現在庫データを分析し、**WOS（Weeks of Supply: 在庫日数/週数）**を算出します。さらに、店舗間で在庫の偏りを無くすための「最適なアイテム移動推奨リスト」および「店舗別WOSサマリー」を自動生成するPythonツールです。

### システム構成（ファイル構成）
プロジェクトは以下のファイル構成で構築されています。

```text
在庫日数（WOS）/
├── run.py                 # ツール実行のエントリーポイント
├── run_wos.bat            # ダブルクリック実行用バッチファイル
├── README.md              # 本ドキュメント（取扱説明書＆引継ぎ書）
├── src/
│   ├── data_loader.py     # 各種CSVデータの読み込み・前処理・フィルタリング
│   ├── wos_calculator.py  # 過去4週間データを基準とするWOS의計算
│   ├── item_allocator.py  # 店舗間の在庫偏りを平準化する移動推奨ロジック
```

## 2. 取扱説明書（ユーザーマニュアル）

### 2.1 動作環境・前提条件
本ツールを実行するには、以下の環境が必要です。
* **Python**: 3.8 以上
* **依存ライブラリ**:
  * `pandas`（データ解析）
  * `numpy`（数値計算）
  * `openpyxl`（Excel出力用）

#### ライブラリのインストール方法
```bash
pip install pandas numpy openpyxl
```

### 2.2 入力データの準備
実行するディレクトリに、以下の2つのCSVファイルを配置してください。どちらも文字コードは **Shift-JIS (CP932)** である必要があります。

1. **売上データ** (デフォルト名: `営業日付別売上分析(旧).csv`)
   * 過去4週間分以上の売上実績が含まれるCSV。
   * ツールは列インデックスを基準にデータを読み込みます（2列目: 営業日付、3列目: 店舗名、4列目: 商品コード、5列目: ブランド名1、7列目: 商品名、9列目: カラー、11列目: 数量）。
2. **在庫データ** (デフォルト名: `在庫一覧.csv`)
   * 現在の各店舗の在庫状況を示すCSV。
   * 2列目: 店舗名、3列目: 商品コード、4列目: 商品名、8列目: ブランド名、18列目: 現在庫（R列）。

### 2.3 実行方法
本ツールは、以下のいずれかの方法で簡単に実行できます。

#### A) ダブルクリックで実行（推奨）
1. ワークスペースのルートにある [run_wos.bat](file:///C:/Users/kesuzuki/Desktop/リテール業務/在庫日数（WOS）/run_wos.bat) をダブルクリックします。
2. 自動的にコマンドプロンプトが開き、ツールが実行されます。
3. 処理完了後、何かキーを押すと画面が閉じます。

#### B) コマンドラインから実行
コマンドプロンプトまたはPowerShellを開き、プロジェクトのルートディレクトリで以下のコマンドを実行します。

```bash

# ファイルパスを指定して実行する場合
python run.py --sales "パス/to/売上データ.csv" --stock "パス/to/在庫データ.csv"
```

### 2.4 出力レポートの確認
処理が正常に終了すると、以下の2つのファイルが出力されます。

1. **`WOS_Report.html` (HTMLレポート)**
   * **アイテム集約リスト**: どの店舗からどの店舗へ、何を何点移動すればよいかを明記した推奨リストです（移動理由も表示されます）。
   * **店舗別WOSサマリー**: SKU×店舗ごとのWOS値を表形式で一覧化したものです。ブラウザのタブで切り替えて確認できます。
2. **`WOS_Report.xlsx` (Excelレポート)**
   * 「アイテム移動推奨リスト」「店舗別WOSサマリー（ピボット形式）」「WOS生データ」の3つのシートが含まれており、再集計や分析に活用できます。

## 3. 開発引継ぎ書（設計・仕様解説）

### 3.1 フィルタリング・ビジネスルール
データ読み込み時（[data_loader.py](file:///C:/Users/kesuzuki/Desktop/リテール業務/在庫日数（WOS）/src/data_loader.py)）に以下のビジネスルールが適用されます。

1. **ブランド制限**
   * ブランド名が **`FJALLRAVEN`** (大文字小文字無視) の商品のみを抽出します。
2. **KANKEN商品の除外**
   * 商品コード（SKU）が **`23510`** で始まるものは、集約対象から除外されます。
3. **Tokyo限定商品の除外**
   * 商品名に **`Tokyo`** (大文字小文字無視) が含まれる商品は、店舗間移動の対象から除外されます。

### 3.2 WOS計算ロジック
WOSの算出は [wos_calculator.py](file:///C:/Users/kesuzuki/Desktop/リテール業務/在庫日数（WOS）/src/wos_calculator.py) で行われます。

* **基準期間**: 売上データ中の「最新の日付」から遡って **過去28日間（4週間）** の売上を合計します。
* **計算式**:
  $$\text{4週平均販売数} = \frac{\text{過去28日間の合計販売数}}{4.0}$$
  $$\text{WOS} = \frac{\text{現在在庫数}}{\text{4週平均販売数}}$$
* **例外処理**: 過去4週間に全く販売実績がない場合（平均販売数 = 0）、ゼロ除算を避けるためWOSは `NaN` (計算不可・空欄) として扱われます。

### 3.3 店舗間移動算出ロジック
店舗間での在庫偏りを解消するため、[item_allocator.py](file:///C:/Users/kesuzuki/Desktop/リテール業務/在庫日数（WOS）/src/item_allocator.py) は以下の手順で移動推奨数を決定します。

1. **平均WOSの算出**:
   SKUごとに、販売実績がある（WOSが計算可能な）全店舗のWOSの平均値（$\text{WOS}_{avg}$）を算出します。
2. **出荷側と受入側の判定**:
   * **出荷側（在庫余剰店舗）**: $\text{WOS} > \text{WOS}_{avg}$ の店舗
   * **受入側（在庫不足店舗）**: $\text{WOS} < \text{WOS}_{avg}$ の店舗
3. **余剰・不足数量の計算**:
   * 出荷側の余剰数: $\text{現在庫} - (\text{WOS}_{avg} \times \text{4週平均販売数})$
   * 受入側の不足数: $(\text{WOS}_{avg} \times \text{4週平均販売数}) - \text{現在庫}$
4. **マッチングと数量決定**:
   * 余剰の最も多い店舗から、不足の最も多い店舗へ順次在庫を割り当てます。
   * 推奨移動数は、小数点以下を**切り上げ**て整数化（`math.ceil`）します。

## 4. 今後の課題と拡張性（TODO）

開発を引き継ぐにあたり、以下の機能追加や改善がロードマップとして挙げられます。

### 4.1 アルゴリズムの改善（移動推奨の最適化）
* **移動効率の考慮**: 現在は余剰店舗と不足店舗を単純に多い順でマッチングしていますが、長距離移動や小口の移動を減らすため、「近隣店舗間での優先マッチング」や「最低移動単位（例: 3点以上から推奨）」などの制限ルールを設けることで、実務上の配送料金や手間を最適化できます。

### 4.2 CSVフォーマット変更への追従
* **列名の動的マッピング**: 現在はCSVの列インデックス（○番目の列）を決め打ちで読み込んでいます。CSVのレイアウトが変更された際のエラーを防ぐため、設定ファイル（YAMLやJSON）で「どの列名がどのデータに対応するか」を動的に指定できる仕組みへの移行を推奨します。

### 4.3 他ブランドや他商品への展開
* **フィルタ仕様 of 外部化**: 現在は `FJALLRAVEN` や `KANKEN` 等のルールがコード内にハードコーディングされています。これらをコマンドライン引数や設定ファイルから切り替え可能にすることで、他ブランド（例: カンケン単体のみ、別ブランドなど）へ容易に横展開できるようになります。

### 4.4 エラーログの強化とリカバリ
* **ログ出力のファイル保存**: 現在は標準出力への print のみです。自動実行された際のエラー検知のため、`logging` モジュールを使用してエラーログをファイル出力し、異常値（列不足や不正なデータ型など）が含まれていた場合の検出・スキップ処理を強化することが望まれます。
